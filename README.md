# Quantum Circuit Partitioning Analyzer

A local OpenQASM 2 workspace for understanding circuit structure, planning
qubit groups with Z3, and sampling the original circuit with Qiskit Aer. The
current planner operates on the qubit interaction graph: it does not decompose
gates or wires, generate executable subcircuits, or reconstruct cut-circuit
results.

## Working features

- Parse and validate OpenQASM 2 circuits, then inspect circuit metrics and the
  weighted two-qubit interaction graph.
- Validate a circuit independently before analysis.
- Browse a line-by-line explanation of the submitted source and gate types.
- Run a Z3 qubit-group planner with a qubit capacity, group limit, and selectable
  objective; inspect assignments and crossing interactions.
- Run an ideal local Qiskit Aer shot simulation of the original circuit.
  Circuits without measurements are measured on a copy before sampling.
- Compare two normalized measurement distributions using total-variation
  distance and classical distribution fidelity; this does not claim circuit
  reconstruction or quantum-state fidelity.
- Generate plain-text or PDF reports from supplied analysis results.
- Export the analysis as JSON or PDF. The browser saves the QASM, analysis,
  partition plan, and simulation result locally across refreshes.
- Navigate through dedicated Home, Dashboard, Upload, Analysis, Requirements,
  Cutting Graph, Optimization, Partitions, Simulation, Comparison, and Report
  screens. Later-stage screens clearly label features that are not implemented.

Exact gate/wire cutting, semantics-preserving subcircuit generation, hardware
mapping/noise, and partitioned-result reconstruction are not implemented. The
UI and API label the planner and simulation scope explicitly.

## Quick start

Use Python 3.11 or newer. From the repository root in PowerShell:

```powershell
py -3.11 -m venv .venv
.\.venv\Scripts\Activate.ps1
python -m pip install --upgrade pip
python -m pip install -r backend\requirements.txt
```

Start the API in one terminal:

```powershell
.\.venv\Scripts\python.exe -m uvicorn app.main:app --app-dir backend --reload --reload-dir backend
```

You can also start it from the repository root with
`.\.venv\Scripts\python.exe backend\app.py`. Backend defaults are in
`backend\.env.example`; frontend defaults are in `frontend\.env.example`.

Start the frontend in another terminal:

```powershell
Set-Location frontend
npm install
npm run dev
```

Open the URL printed by Vite (normally <http://127.0.0.1:5173>). The frontend
uses Vite's `/api` proxy to reach the backend on port 8000, so the browser does
not need a separate CORS/API-port setting. If you set `VITE_API_URL` in
`frontend/.env`, restart Vite for the change to take effect. The frontend
rechecks backend health every five seconds and recovers automatically when the
API starts again.

The built-in Bell-state example is loaded automatically when the backend is
available. Paste OpenQASM 2 or upload a `.qasm`/`.qasm2` file (up to 1 MB),
then run the analysis before using the planner or simulator. If a backend from
an older version is already running, stop it and restart the command above so
the current `/api/optimize` and `/api/simulation/original` routes are loaded.

## API

- `GET /api/health` — backend readiness and available features.
- `POST /api/circuits/validate` — validate QASM and return register/operation
  sizes.
- `POST /api/circuits/analyze` — body: `{"qasm": "<OpenQASM 2 source>"}`.
- `POST /api/optimize` — body: `qasm`, `max_qubits_per_partition`,
  optional `max_partitions` (default 4), `objective` (`balanced`,
  `minimize_cuts`, or `minimize_partitions`), and optional `timeout_ms`
  (default 5000).
- `POST /api/simulation/original` — body: `qasm`, optional `shots` (default
  1024, maximum 100000), and `random_seed` (default 42; `null` disables a fixed
  seed). The original OpenQASM is reused automatically from the analysis page.
- `POST /api/partitions/plan` — alias of the structural planner.
- `POST /api/comparison/distributions` — compare two normalized measured
  outcome distributions.
- `POST /api/reports/generate` — render supplied result sections as plain text.
- `POST /api/reports/pdf` — download a PDF containing supplied result sections.

Example request:

```json
{
  "qasm": "OPENQASM 2.0;\ninclude \"qelib1.inc\";\nqreg q[2];\nh q[0];\ncx q[0],q[1];",
  "shots": 1024,
  "random_seed": 42
}
```

The response includes `simulation_status`, circuit metrics, shot counts,
probabilities, the most probable outcome, and timing. Outcome values are
generated by Aer for the submitted QASM; they are not fixed in the application.

Circuits are limited to 64 qubits and 10,000 instructions by the validator.
The local simulator additionally limits simulation to 20 qubits.
